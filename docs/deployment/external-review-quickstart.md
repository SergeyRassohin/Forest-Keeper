# Forest Keeper: инструкция внешнему проверяющему

## 1. Что это за продукт и что вы проверяете

Forest Keeper — приложение для сравнения данных из разных источников. Оно должно находить записи об одной сущности, показывать различия и помогать человеку выбрать обоснованное решение. Источники остаются без изменений. Пример бизнес-сценария: сравнить выгрузки номенклатуры из 1С и Excel, заметить расхождение массы одной детали и сохранить решение специалиста.

Текущая версия позволяет проверить **вход → два источника → импорт → нормализацию → просмотр происхождения → сохранность после перезапуска**. Сопоставление в main ещё отсутствует; конфликты, бизнес-решения и AI-рекомендации также отсутствуют. Их отсутствие уже известно и не должно заставлять вас искать несуществующие кнопки. Полный критерий MVP остаётся обязательным: [готовность и блокеры](review-readiness.md).

Короткий словарь:

| Термин | Значение |
| --- | --- |
| Источник | Название набора данных, например «Выгрузка Excel» |
| Пакет / ImportBatch | Одна загруженная версия файла и результат её импорта |
| Raw | Исходные значения без исправлений |
| Provenance / происхождение | Из какого источника, файла, строки или XML-элемента взято значение |
| Нормализация | Приведение значения к объявленному формату; например граммов к килограммам |
| Профиль | Явные правила: где искать поля и как их преобразовывать |
| Evidence | Сохранённые основания вывода; в текущей нормализации — значения, правила и происхождение |
| Decision | Будущее сохраняемое бизнес-решение человека по конфликту; это не статус импорта |
| Forest Codex | Будущий версионируемый набор утверждённых критериев клиента; не AI и не инструмент OpenAI Codex |

## 2. Подготовка машины

Поддерживаемый путь для этой инструкции: Linux с Bash либо Windows с WSL2/Ubuntu; на macOS — Bash и Docker Desktop. На Linux установите Docker Engine и Compose plugin, на Windows/macOS — Docker Desktop. Docker должен быть запущен. Используйте отдельную тестовую машину и несекретные данные.

Нужны [Git](https://git-scm.com/downloads), [Docker Engine](https://docs.docker.com/engine/install/) или [Docker Desktop](https://docs.docker.com/desktop/), [Compose plugin](https://docs.docker.com/compose/install/), Bash, OpenSSL и curl. В WSL2 команды ниже выполняются внутри Ubuntu. На macOS curl/OpenSSL доступны в терминале; на Ubuntu при необходимости: `sudo apt-get install git openssl curl` после установки Docker по официальной инструкции.

```bash
git --version
docker --version
docker compose version
bash --version
openssl version
curl --version
docker info
```

Все команды должны завершиться успешно. `permission denied` на Docker означает, что доступ к daemon ещё не настроен; следуйте [инструкции Docker для Linux](https://docs.docker.com/engine/install/linux-postinstall/). Не начинайте запуск до исправления.

Для небольшой проверки без AI планируйте 4 CPU, 8 GB RAM и 15 GB свободного диска как стартовую конфигурацию, не как измеренный минимум. Сборка скачивает зависимости и образы, поэтому первый запуск требует Интернет и может занять несколько минут. GPU для текущего сценария не нужен. AI имеет отдельные [требования и блокеры](../ai/model-downloads.md).

Python, uv и Node.js на хосте для базовой проверки не нужны. Не скачивайте Qwen для импорта и нормализации: текущий путь их не использует.

## 3. Получение проекта

```bash
git clone https://github.com/SergeyRassohin/Forest-Keeper.git
cd Forest-Keeper
git rev-parse HEAD
git status --short
```

Сохраните SHA из `git rev-parse HEAD` в отчёт. По умолчанию проверяется main. Для проверки отдельного PR нужен его явно согласованный commit; результаты другой ветки не доказывают готовность main. Все дальнейшие команды выполняются из каталога Forest-Keeper.

## 4. Инициализация и запуск

```bash
bash scripts/dev-init.sh
docker compose up --build -d --wait --wait-timeout 180
docker compose ps -a
curl --fail --retry 15 --retry-connrefused --retry-delay 1 \
  --cacert deploy/local/tls/dev.crt https://localhost:8443/api/v1/health
```

`dev-init.sh` создаёт локальные секреты в `.env` и тестовый сертификат в `deploy/local/tls/`. Не публикуйте их. Повторный запуск сохраняет существующую конфигурацию.

Ожидается: `postgres`, `redis`, `backend`, `worker`, `frontend` работают; у сервисов с healthcheck — healthy. Одноразовый `migrate` должен закончиться **Exited (0)**: это нормально. Остальные Exited/Restarting или unhealthy требуют диагностики. Health возвращает HTTP 200 и `status: ok`; API, database, redis имеют `ok`. При медленной загрузке образов повторите команду запуска после завершения сборки.

Откройте **https://localhost:8443** в браузере на этой же машине. Сертификат тестовый, самоподписанный; разрешите его только для своего localhost. Не отключайте TLS-проверку глобально. Срок сертификата — 30 дней.

Если приложение развёрнуто на удалённом Linux-сервере, используйте SSH-туннель с машины, где открыт браузер:

```bash
ssh -L 8443:127.0.0.1:8443 user@server
```

Замените `user@server` своими реквизитами; оставьте терминал открытым и зайдите на https://localhost:8443. Приглашение доверить сертификат ожидаемо. Публичный доступ по IP и production TLS требуют отдельной [серверной конфигурации](server-installation-v0.1.md).

## 5. Первый вход и роли

На чистой установке пользователей ещё нет. Создайте первого администратора:

```bash
docker compose exec backend python -m app.auth.bootstrap --login admin --full-name "Администратор проверки"
```

Введите новый пароль длиной 12–128 символов в скрытом приглашении. Готового пароля нет. Команда работает только при пустой таблице пользователей. Если пользователи уже есть, используйте существующую учётную запись; не удаляйте volumes ради повторного bootstrap.

В браузере введите `admin` и выбранный пароль. Видны «Состояние сервера» и «Импорт данных». Внизу страницы «Состояние сервера» расположен блок «Пользователи»; создайте аккаунт `reviewer` с ролью REVIEWER, а для отрицательной проверки — `viewer` с ролью VIEWER; задайте свои пароли. Создание требует входа не старше 5 минут: при соответствующей ошибке выйдите и войдите снова.

ADMIN создаёт источники и пользователей, запускает импорт/нормализацию. Будущие бизнес-решения требуют REVIEWER/DATA_OWNER; ADMIN эти права не наследует. REVIEWER может работать с уже созданными источниками. VIEWER просматривает данные, но не запускает обработку. [Подробности прав и сессий](../development/authentication.md).

`/api/v1/version` защищён: запрос curl без cookie даст **401**, это ожидаемо. После входа ADMIN можно открыть https://localhost:8443/api/v1/version в том же браузере. Публичная проверка готовности — только `/health`.

## 6. Проверка двух источников на готовых примерах

Начните с небольшого примера, чтобы отличить проблему установки от неподдержанного формата вашего файла.

В «Импорт данных» под ADMIN раскройте «Добавить источник». Создайте два источника:

| Название | Код | Тип |
| --- | --- | --- |
| USGS CSV | usgs_csv | Файловая выгрузка (FILE) |
| USGS XML | usgs_xml | Файловая выгрузка (FILE) |

Используйте файлы [открытого примера](../../tests/data/external-review/README.md):

- для первого источника: `tests/data/external-review/source-a.csv`;
- для второго: `tests/data/external-review/source-b.xml`.

Оба файла получены из одного открытого каталога землетрясений USGS. Во втором намеренно изменено форматирование. Это две учебные выгрузки, а не доказательство независимости источников. Они позволяют проверить данные из сети без информации заказчика. Это не утверждённый промышленный домен FK.

Выберите источник и файл, нажмите «Загрузить». Дождитесь «Завершён» (COMPLETED). Откройте пакет по имени файла. Проверьте источник, имя, SHA-256, число записей и исходные значения. Для XML проверьте позицию элемента, для CSV — строку. В каждом пакете должны присутствовать все строки своего файла.

В блоке «Нормализация» выберите **public-earthquake v1** и нажмите «Нормализовать пакет». Дождитесь COMPLETED и раскройте результат. Профиль содержит только id, название места, магнитуду и время события; нормализация регистра/пробелов должна дать одинаковые id/name для одинакового события в двух файлах. Raw во втором файле должен сохранить исходные пробелы/регистр. Поле времени сохраняется строкой, без выдуманного часового пояса. Число и конкретные ожидания — в README примера.

Повторите под REVIEWER с уже созданным источником. Под VIEWER проверьте просмотр и отсутствие кнопок загрузки/нормализации. Запишите ошибки или неожиданные результаты.

Для проверки единиц, дат и ошибочных значений отдельно загрузите `tests/data/normalization/material.csv` и `tests/data/normalization/onec.xml`; второй источник должен иметь тип «Выгрузка 1С». Выберите **synthetic-material v1**. Массы `12,5 кг`, `12500 г` и `12.500 KG` становятся `12.5 kg`; неоднозначные значения остаются UNKNOWN/INVALID. Это синтетический тест, не реальная выгрузка клиента.

## 7. Ваш собственный файл

Поддерживаются UTF-8 CSV с заголовком, первый лист XLSX с заголовком и XML профилей из [описания импорта](../development/import.md). Размер — до 100 000 000 байт. Макросы/формулы, повреждённые документы и небезопасный XML не являются поддерживаемым обычным вводом.

Создайте отдельный источник, загрузите свой несекретный файл и проверьте raw/provenance. **Успешный импорт не означает, что система понимает семантику всех колонок.** Для нормализации используйте профиль с подходящими именами и путями. Текущего браузерного редактора mapping нет. Если подходящего профиля нет, зафиксируйте `BLOCKED: требуется mapping profile` и приложите только структуру/обезличенный пример. Не переименовывайте поля в файле ради видимости совместимости и не выбирайте Material для чужого домена.

Для generic XML исходный профиль ожидает элементы `<records><record>…</record></records>`; произвольная производственная выгрузка 1С без проверки её структуры не гарантируется.

## 8. Сохранность после перезапуска

Запишите IDs двух пакетов и запусков нормализации, значения и SHA-256 из карточек. Выполните:

```bash
docker compose restart postgres redis backend worker frontend
```

Дождитесь health 200 той же командой из шага 4, обновите страницу и при необходимости войдите снова. Найдите те же пакеты и запуски: IDs, исходные значения и результаты должны сохраниться. Можно также выполнить `docker compose down`, затем `docker compose up -d --wait --wait-timeout 180` — без `-v`.

**Не выполняйте `docker compose down -v`: это удалит данные.** Сейчас проверяется сохранность импорта/нормализации; проверка сохранённого Decision заблокирована его отсутствием в main.

## 9. Сопоставление, решения и AI: где остановиться

В main ещё нет экрана сопоставления, Conflict, Decision Registry и рекомендаций. Зафиксируйте эти пункты как **BLOCKED**, не как PASS или незаметный SKIP. Описание [PR #15](https://github.com/SergeyRassohin/Forest-Keeper/pull/15) не означает, что matching уже есть в вашей сборке.

Согласованная политика matching: нечёткое совпадение требует ручного подтверждения; автоматическое подтверждение допускается только по согласованному однозначному точному ключу без противоречий. Процент похожести не даёт разрешения автоматически объединять записи.

Для подготовки Qwen есть [проверенные ссылки и команды получения файлов](../ai/model-downloads.md). Модельные файлы сами по себе не добавляют отсутствующие функции. Запуск поддерживаемых AI services, `/internal/ai/model-info`, embeddings и проверка рекомендаций ещё являются блокерами #18. Не заменяйте Qwen моделью с похожим названием.

После реализации полного пути потребуется: подтвердить/исправить конфликт → записать Decision ID → перезапустить → найти тот же Decision → загрузить похожий случай → увидеть ссылку на прошлый Decision в рекомендации → остановить LLM и проверить доступность истории. Сейчас эти шаги не исполнимы.

## 10. Диагностика и отчёт

```bash
docker compose ps -a
docker compose logs --tail=100 migrate backend worker frontend
curl --cacert deploy/local/tls/dev.crt https://localhost:8443/api/v1/health
git rev-parse HEAD
```

Для ошибки БД/Redis дополнительно посмотрите `docker compose logs --tail=100 postgres redis`. Не прикладывайте `.env`, пароли, cookies, ключи или необезличенные входные данные. Не включайте полный дамп переменных окружения.

| Симптом | Что проверить |
| --- | --- |
| Страница не открывается | Docker работает; frontend запущен; порт 8443 свободен; для сервера открыт SSH-туннель |
| Health 503 | Завершение migrate, доступность PostgreSQL/Redis, текущая версия схемы |
| Вход 403 | Адрес https://localhost:8443; Origin входит в FK_ALLOWED_ORIGINS; не используется иной hostname |
| Вход 429 | Подождите 60 секунд после слишком частых попыток |
| Создание пользователя 403 | Войдите заново под ADMIN и создайте в течение 5 минут |
| Импорт долго в очереди | Состояние worker и его logs |
| Нормализованных полей нет | Профиль соответствует формату, типу источника и путям полей |
| Qwen не скачивается | [Команды диагностики и проверка контрольных сумм](../ai/model-downloads.md) |

Шаблон отчёта:

```text
Commit SHA:
ОС / RAM / CPU:
Docker / Compose / браузер:
Сценарий и номер шага:
Файл, размер и профиль (без секретных данных):
Ожидалось:
Получилось:
PASS / FAIL / BLOCKED:
ID пакета / запуска / Decision, если существует:
Точный текст ошибки и обезличенный фрагмент логов:
Важность: blocker / major / minor / suggestion
```

Отдельно оцените: стало ли понятно назначение продукта, удалось ли развернуть его без подсказок, видна ли связь raw и нормализованных значений, понятны ли ограничения, сохранилась ли история. Успех текущей проверки этапов 0–3 не равен приёмке полного MVP.
