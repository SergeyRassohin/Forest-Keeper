# Forest Keeper — Client Access Model v0.1

## Основной принцип
Backend и API Forest Keeper не должны зависеть от типа пользовательского клиента.

## Desktop Client
Рекомендуемый вариант для заказчиков с жёсткими ИБ-требованиями.

Преимущества:
- централизованная установка только на разрешённые ПК;
- возможность device certificate / mTLS;
- отсутствие штатной точки входа у ПК без клиента;
- централизованное обновление;
- дополнительный контроль доверенного устройства.

Ограничение: наличие desktop-клиента само по себе не является security boundary. Сервер/API также должны ограничивать сетевой и identity-доступ.

## Web Client
Допустимая альтернатива.

- работает через корпоративный браузер;
- HTTPS;
- SSO/MFA;
- browser policies;
- network restrictions.

## Двухфакторная логика доверия

```
доверенное устройство
→ защищённый канал
→ идентификация пользователя
→ FK role/RBAC
→ разрешённые операции
```

Device trust и user identity — разные проверки.

## DTO
Клиент получает прикладные JSON DTO:
- entity;
- conflict;
- recommendation;
- provenance;
- available actions.

Клиент не должен напрямую читать PostgreSQL или внутренние raw storage.
