# Самостоятельная проверка Forest Keeper: сценарий и чеклист

[К содержанию](README.md) · [Установка](installation.md) · [Интерфейс](user-guide.md) · [Ошибки](troubleshooting.md)

**Назначение:** один человек на своём ПК проверяет *проверяемый `main`*, а не промышленную готовность AI. Все файлы из репозитория синтетические/учебные. Заполняйте PASS/FAIL/BLOCKED; если действие невозможно, не подменяйте его успехом.

## Карточка прогона
```text
Дата:
ОС:
CPU / RAM:
Docker / Compose:
git branch:
git rev-parse HEAD:
Браузер:
Результат (PASS / FAIL / BLOCKED):
```

## A. Установка и доступ
- [ ] A1. Выполнены все команды из [установки](installation.md); `docker info` работает.
- [ ] A2. `main` скачан; полный SHA записан; `git status --short` пуст.
- [ ] A3. `bash scripts/dev-init.sh` и `docker compose up --build -d --wait --wait-timeout 180` завершены без отказа.
- [ ] A4. `migrate` = Exited (0), базовые сервисы active/healthy, /api/v1/health даёт HTTP 200.
- [ ] A5. Вход `admin` создан через bootstrap; `reviewer` создан и получил явный учебный scope.
- [ ] A6. Переключатель светлой/тёмной темы работает, выбор сохраняется после обновления страницы.

## B. Два источника и нормализация
**Учебные файлы:** `tests/data/conflicts/source-a.csv` (тип FILE) и `tests/data/conflicts/source-b.xml` (тип ONE_C / 1С). Для каждого создайте отдельный источник в «Импорт данных», например `demo_csv_01` и `demo_onec_01`. Если эти коды уже заняты после предыдущего прогона, используйте новые, не стирайте старые данные.

- [ ] B1. ADMIN создал два источника с разными кодами и правильным типом.
- [ ] B2. CSV и XML загружены; оба ImportBatch = COMPLETED; записаны ID.
- [ ] B3. Открыты исходные записи: позиции, raw и SHA-256 файлов доступны.
- [ ] B4. Для каждого пакета запущена нормализация профилем `synthetic-material v1`; оба AnalysisRun = COMPLETED; ID записаны.
- [ ] B5. В raw остались первоначальные строки/единицы; нормализованные значения показаны отдельно.

## C. Сопоставление и два конфликта
- [ ] C1. В «Сопоставление» выбран `synthetic-material v1` и два **именно этих** AnalysisRun; matching = COMPLETED.
- [ ] C2. В карточке видны оба источника, основания matching, raw/normalized, версии и provenance.
- [ ] C3. Открыта функция «Открыть конфликты сопоставления» → «Проверить конфликты», анализ = COMPLETED.
- [ ] C4. **Ожидаются ровно 2 конфликта**: `mass VALUE_MISMATCH` для `DIFF` и `mass MISSING` для `MISS`. `EQ` с эквивалентными массами не даёт конфликта.
- [ ] C5. Открыт `VALUE_MISMATCH`: видны оба исходных значения, kg, источник, Basis, hash/позиция и версия. Записан Conflict ID.

**Если ровно 2 конфликта не получились:** остановите сценарий здесь; проверьте, что использованы **conflicts**, а не **matching/external-review** fixture, и совпадают профили и запуски. Не «исправляйте» входные данные ради красивого результата.

## D. Человек принимает Decision
- [ ] D1. Выйти из ADMIN, войти как `reviewer` с разрешённым scope.
- [ ] D2. Открыть `VALUE_MISMATCH` → «Начать рассмотрение» → выбрать значение одного из существующих источников → вписать осмысленную причину (например «Учебная проверка: выбран источник A по заданию сценария»).
- [ ] D3. Нажать «Проверить перед сохранением»; проверить источник/значение/причину; отдельно подтвердить «Сохранить решение».
- [ ] D4. Получен **Decision ID**. Через «Открыть решение в реестре» проверены автор, дата, причина, выбранное значение и контекст. Записать ID.
- [ ] D5. Обновить страницу, найти **тот же Decision ID** и ту же причину. Raw обоих источников не изменён.
- [ ] D6. Для оставшегося `MISSING` отметить «Недостаточно данных» или отложить. Отложенный кейс не должен притворяться успешно RESOLVED.

**Опционально:** ещё раз рассмотрите первый конфликт и создайте новую подтверждённую версию решения. Старое должно сохраниться как историческое/superseded, а новое стать active. Это проверяет неизменяемость Registry. Не делайте это, если хотите оставить один простой кейс.

## E. Проверка рекомендаций без ложного AI PASS
- [ ] E1. В `main` проверьте экран похожих решений/рекомендаций и запишите **фактически показанный** reason/status.
- [ ] E2. Если production provider = UNAVAILABLE/ABSTAINED, зафиксировать **EXPECTED LIMITATION**, а не FAIL установки.
- [ ] E3. **Не утверждать**, что Qwen сделал рекомендацию: Stage 9 не в `main`. Положительный demo на synthetic embeddings допускается только по отдельной dev/test инструкции, не в этом тесте.
- [ ] E4. Убедиться, что даже при недоступной рекомендации Human Review и Decision Registry продолжают работать.

## F. Перезапуск без потери данных
Убедитесь, что нет активных долгих обработок. Из корня репозитория:
```bash
docker compose stop -t 30 worker
docker compose restart postgres redis backend frontend
docker compose up -d --wait --wait-timeout 180 worker
```
- [ ] F1. Health снова HTTP 200.
- [ ] F2. Открыты **те же** ImportBatch/AnalysisRun/Conflict/Decision ID.
- [ ] F3. Raw, Basis и причина Decision совпадают с записанными.
- [ ] F4. После перезапуска можно авторизоваться и открыть прежний кейс.

**Никогда не выполняйте `docker compose down -v`**: это удаляет volumes.

## G. Минимальная проверка ограничений прав
- [ ] G1. ADMIN без бизнес-роли не видит кнопок принятия Decision.
- [ ] G2. VIEWER (если создан) может просматривать разрешённые данные, но не менять решения.
- [ ] G3. Неиспользуемый/чужой domain scope не раскрывает чужие кейсы. Не добавляйте всем пользователям права ради прохождения теста.

## Итоговый протокол
```text
A Установка: PASS/FAIL/BLOCKED:
B Импорт и нормализация:
C Matching и 2 конфликта:
D Human Decision и Registry:
E Similarity/Recommendation: EXPECTED LIMITATION / PASS / FAIL:
F Restart и неизменность:
G RBAC:
Основной путь A-D+F: PASS / FAIL / BLOCKED:
Известные ограничения: Stage 9/Qwen production BLOCKED.
Ошибки (шаг, текст, обезличенные логи):
Общий вердикт «готово к локальному демо» / «нужны исправления»:
```
**Критерий успешной личной проверки:** A–D и F пройдены, бизнес-решение сохранено и найдено после restart; E честно зафиксирован как ограниченный функционал. Это **не равно** полной внешней/промышленной приёмке, которая остаётся открытой по #18/#20/#31.
