## Architecture and product intent

- Exact Qwen3-8B-GGUF Q4_K_M revision/hash, configured32768context and Qwen3-Embedding-0.6B revision/hash/1024dimensions match the approved manifest and14-file lock. No substitute model/space/runtime is silently accepted. All tokenizer/config/pooling/license/card files require byte verification, not only weights. Actual runtime/model-info/offline checks remain future gates.
- Separate model-agnostic embedding/LLM contracts and isolated `ai/` heavy dependency lock keep torch/transformers/weights out of the business backend. CPU torch comes from an explicit source index. Resolver pins are candidates, not proof of runtime compatibility/SCA acceptance.
- Distinct LOCAL_QWEN_DEMO provider/version with artifact/preprocessing/runtime identity preserves synthetic-test IDs and prevents equal-dimension space mixing. Dual indexes, complete coverage, explicit activation/rollback and immutable Decision/raw remain. Production is hard-disabled in this implementation even if flags/service health claim otherwise; any future accepted record must bind approved labels/dataset/split/metric code/targets and exact model/preprocessing/runtime/retrieval/policy digests plus owner approval.
- LLM cannot select business truth or mutate Decision/Rule/Template/Codex/source. It returns allowlisted evidence references and bounded fact-clause codes, exact deterministic status/action/fingerprint. Backend independently validates facts/references and renders explanation from validated clauses. Empty or generic-warning-only output is invalid; required clauses must describe current case, real support/abstention and limitations. This is a defensible grounding contract; schema-valid arbitrary prose is not assumed true. Actual Qwen generation is mandatory and cannot be replaced with fixtures for real-model acceptance.
- Internal embedding route and four AI routes are separate from public backend/proxy, use fixed local allowlisted transport with redirects/proxy/client URLs disabled, file-backed service capability, private runtime network, no model DB/import mounts or published AI ports. Core startup does not depend on AI readiness. Model-only bridge/loopback DNS/no external route are design controls whose actual DNS/HTTP denial must be tested; offline environment flags alone are insufficient. Dedicated worker must not become an outbound proxy or gain external egress through a second network.
- Public POST explicitly requests asynchronous explanation; public GET only polls. Existing cookie/Origin/scope and opaque actor/session/case-bound handles remain. All three existing permissions `conflict.view`, **`decision.view`**, `recommendation.view` are required at admission, fresh input construction and delivery. XLSX rows12/17/19 independently confirm the codes and current four-role grants; coincident identical role sets do not justify dropping decision.view. Explanation grants no `recommendation.accept_as_decision` or business commit authority.
- Separate Qwen embedding and LLM queues move both query preparation and historical backfill/recovery off the import worker. Bounded checkpoint yielding avoids query starvation. Atomic global admission/per-actor user admission, idempotent handles, wait expiry, cancellation/stale cleanup and restart reconciliation bound jobs; operator-derived backfill uses a server namespace rather than fabricated human identity.
- Fresh session/user/roles/scope and all relevant case/head/provider/prompt/policy/source-map digests are checked before input and delivery. Snapshot closes before long inference; no gate/SQL lock held during model generation. Work may finish after revoke but cannot be delivered. Redis/model failure leaves manual review/history intact.
