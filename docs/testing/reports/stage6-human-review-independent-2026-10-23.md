## Concrete implementation follow-up

**R1 — deferred lifecycle consistency after insert (defense in depth, requires retest).** `0007_decisions.py:check_conflict_decision_head` permits IN_REVIEW with any effective head. This is necessary when explicit correction starts while retaining an earlier final head, but also permits a newly inserted SELECT_VALUE/ENTER_VALUE/INSUFFICIENT_DATA Decision to commit without its expected final Conflict state if the application forgets the final update. The main safety invariant (no RESOLVED without a valid Decision) is protected; the converse complete outcome/lifecycle mapping is not yet DB-enforced. Ensure service transitions atomically and test rollback; preferably add an insert-event-specific deferred check that, when NEW is still the effective head at commit, requires RESOLVED for SELECT_VALUE/ENTER_VALUE, INSUFFICIENT_DATA for INSUFFICIENT_DATA, and IN_REVIEW for DEFERRED. A later transaction starting correction with an existing head must remain allowed.
