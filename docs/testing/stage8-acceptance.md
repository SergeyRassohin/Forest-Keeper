# Stage 8 — сценарий приёмки

Основание: [issue #29](https://github.com/SergeyRassohin/Forest-Keeper/issues/29),
[утверждённая policy](../development/recommendations.md) и Decision Log от 25 октября 2026.
Реализация в PR #30; выполнение сценария не разрешает автоматический merge.
AI/LLM, Rules/Codex и внешний MVP #17/#18/#20 остаются отдельными работами.

## Подготовка

Использовать отдельную тестовую установку, синтетические данные и действительные
учётные записи DATA_OWNER, REVIEWER, VIEWER и ADMIN. ADMIN без бизнес-роли не может
принимать Decision. Данные клиента не нужны. Сохранить точный SHA, версии образов,
policy и явно назначенную карту соответствия источников.

В обычной конфигурации положительная рекомендация отключена. Для демонстрации
оператор явно включает test/development и существующий synthetic provider, назначает
двум действительным источникам логические роли через versioned source map. Названия
источников и порядок A/B не являются таким назначением. Конфигурация не передаётся
из браузера. При замене карты остановить/дождаться завершения всех API/worker
операций, заменить одинаковую конфигурацию всех процессов и запустить их снова.

Автоматический браузерный сценарий готовит изолированную установку сам:

```bash
FK_GALLERY_BACKEND_IMAGE=<собранный-backend> \
FK_GALLERY_FRONTEND_IMAGE=<собранный-frontend> \
FK_ENV_FILE=<закрытый-файл-конфигурации> bash scripts/capture-ui-gallery.sh
```

Он удаляет только собственную временную установку и её синтетические тома.
Файлы конфигурации с паролями, cookie и e2e.json не коммитить.

## Основной браузерный путь

1. Войти как DATA_OWNER. Загрузить CSV и 1С XML одного нового случая, нормализовать,
   сопоставить и сформировать конфликт массы. Проверить исходные значения и Basis.
   При отсутствии пяти независимых прецедентов готового действия и confidence нет.
2. Повторить путь для пяти разных случаев: новые файлы/ключи/исходные записи,
   сопоставимые наименования, отдельный Conflict для каждого. Каждый раз начать
   рассмотрение, самостоятельно выбрать один и тот же логический источник,
   ввести причину, подтвердить диалог и сохранить действительный Decision ID.
3. Создать шестой совместимый случай. Дождаться окончания индексации и открыть
   похожие решения. В рекомендации видны пять действительных прошлых Decisions,
   число независимых групп, текущий предлагаемый source/value и явная надпись
   о демонстрационном режиме. Проценты вероятности отсутствуют; authority NOT_DEFINED,
   Rules/Template/Codex NOT_CONFIGURED.
4. Включить тёмную тему, открыть основание прошлого Decision и вернуться. Обновить
   страницу: тёмная тема, маршрут и ID текущего конфликта сохраняются. Чужие данные
   не появляются. Текст незавершённой формы после reload не обязан сохраняться.
5. Начать рассмотрение шестого случая. Обновлённая рекомендация учитывает новый token.
   Нажать «Использовать предложение в форме»: выбран текущий source/value, но Decision
   ещё не создан. Ввести причину, переключить обе темы — причина, radio и карточка
   сохраняются. Через отдельный диалог подтвердить сохранение. В Registry новый
   immutable Decision с серверным provenance receipt и relationship MATCHED.
6. Создать следующий случай, применить предложение в форме, затем вручную выбрать
   другой источник. Сохранить с обоснованием. Автоматически приложенная reference
   очищена; это самостоятельный Decision человека. История не переписывается.
7. Создать ещё один совместимый случай. После индексации разных исходов рекомендация
   воздерживается и показывает противоречие, даже если большинство выбирало один
   источник. Ручной путь остаётся доступен.

## Отказы и безопасность

- Один/четыре независимых прецедента, пять коррелированных повторных импортов,
  неизвестная/неоднозначная source map, ENTER_VALUE в истории: нет готового действия.
- Более20 above-threshold прецедентов: EVIDENCE_WINDOW_EXCEEDED без скрытой пагинации.
- Пять пригодных и один совместимый non-INDEXED skip: INDEX_COVERAGE_UNCERTAIN,
  без частичной положительной рекомендации. Несовместимый skipped случай не блокирует.
- Production с любыми synthetic opt-in flags: UNAVAILABLE, action/confidence=null.
- VIEWER читает только разрешённую область, не сохраняет Decision. ADMIN без
  REVIEWER/DATA_OWNER не получает бизнес-полномочия. После реального logout/отзыва
  scope старые ссылки не раскрывают историю, IDs или counts; неизвестный/чужой ID
  возвращает одинаковый404. Клиентские policy overrides отклоняются422.
- Устаревший token/receipt после reopen/смены версии:409. Два человека с одним
  token получают один201 и один409. Исторический reopen и отзыв scope не проходят
  внутрь атомарного принятия. Повреждённый receipt/lineage даёт безопасный отказ.
- Similarity и Recommendation делят лимит120 authenticated reads/min/actor.
  Общая SQL/lock работа ограничена1500ms, pooled timeout восстанавливается.
  GET не изменяет исходники, Conflict, Decision, Rule и не запускает embedding/job.
- При недоступном Redis новое чтение рекомендации503; независимый ручной Decision
  сохраняется. Точный повтор уже committed запроса с reference возвращает прежний
  receipt после текущей авторизации, без повторного Decision.

## Темы и доступность

Проверить вход, импорт/нормализацию, Matching, Conflict, Human Review, Registry,
Similarity и Recommendation в обеих темах на desktop/mobile. Клавиатурный focus
виден; статус понятен без цвета; таблицы прокручиваются внутри контейнера.
Первая загрузка учитывает системную тему до React, явный выбор имеет приоритет,
недоступный localStorage не ломает вход и переключение. Настройка темы не попадает
в business evidence. Axe WCAG2.2 AA и прежние responsive thresholds не ослабляются.

## Автоматические gates

Обязательны все команды issue #29 §11: check.sh, check-sast.sh, check-secrets.sh,
test-security-gates.sh, check-dependencies.sh, check-integration.sh; реальная HTTPS
галерея; production smoke; независимое architecture/security/product ревью.
Дополнительные opt-in harnesses в backend/tests:

- benchmark_recommendations.py:100/1k/10k фактических Decision/vector rows,
  десять отдельных сессий, Stage7 baseline/Stage8 p50/p95/max/outcomes, планы и RSS;
  copied provenance не доказывает независимость/семантику,100k и fully cold не заявлены.
- restart_recommendations.py: только собственный fk-stage8 стенд, реальные HTTPS
  импорты/подтверждения, устойчивый receipt после полного restart, partial backfill,
  explicit version activation/stale, ошибки PostgreSQL/Redis, независимый ручной путь.
  Факты/файлы/тома сохраняются, временный вход отзывается, default fail-closed возвращается.

Итоговый отчёт связывает source SHA, actual image IDs, логи/артефакты и замечания
ревью. Push/PR CI должен быть зелёным на exact final HEAD. Остановиться на READY TO
MERGE; решение о merge остаётся владельцу.
