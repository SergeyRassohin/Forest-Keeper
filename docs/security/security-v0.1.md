# Forest Keeper — Security v0.1

## Принцип
В MVP безопасность начинается с архитектурного ограничения: Forest Keeper читает внешний мир, но не изменяет его.

## Контроль доступа
- роли VIEWER / REVIEWER / DATA_OWNER / ADMIN;
- каноническая матрица разрешений MVP: `docs/security/access-control-matrix-v0.1.xlsx`;
- backend обязан проверять permission независимо от frontend;
- должность человека и роль FK не смешиваются;
- ADMIN является системной/технической ролью и сам по себе не получает право принимать бизнес-решения по Conflict;
- для принятия бизнес-решений требуется соответствующая роль/permission REVIEWER или DATA_OWNER;
- для административного доступа предусмотреть усиленную аутентификацию;
- least privilege.

## Защита исходных систем
- MVP только read-only;
- AI не имеет прав записи;
- AI confidence не является permission;
- будущая запись должна выполняться отдельным Publisher с allowlist операций и после Human Approval.

## Секреты
- не хранить credentials в коде и репозитории;
- secret scanning в CI;
- отдельное защищённое хранилище секретов;
- plaintext-пароли и токены в логах запрещены.

- изменения ролей/permission;
- лицензионные действия.

## AI security
Тестировать:
- prompt injection через PDF/Excel/XML;
- попытку заставить модель игнорировать правила;
- утечку данных между контекстами;
- извлечение system prompt;
- попытки инициировать запрещённые действия.

## CI security gates
- SAST/SCA/secrets checks;
- dependency vulnerability scan;
- Critical vulnerability блокирует release до устранения или явного документированного исключения;
- RBAC tests обязательны для permission из Access Control Matrix.

## Независимая проверка
Перед серьёзным промышленным пилотом требуется независимый pentest.
