# Forest Keeper — Licensing v0.1

## 1. Компоненты

### FK License Generator
Внутренняя служебная программа поставщика.

Устанавливается только у разработчика/поставщика Forest Keeper.

Назначение:
- создать лицензию;
- задать параметры лицензии;
- подписать лицензию закрытым ключом;
- сформировать файл `forestkeeper.license`.

### License Service
Компонент, установленный у заказчика внутри FK Server.

Назначение:
- проверить цифровую подпись лицензии открытым ключом;
- проверить срок;
- проверить редакцию;
- проверить доступные модули;
- применить лицензионные ограничения.

Закрытый ключ поставщика никогда не передаётся заказчику.

## 2. Содержимое лицензии

Пример логической структуры:

```json
{
  "license_id": "FK-2026-000123",
  "customer": "ООО Ромашка",
  "edition": "Enterprise",
  "valid_from": "2026-10-01",
  "valid_until": "2027-09-30",
  "support_until": "2027-09-30",
  "modules": ["core", "entity-resolution", "recommendations"],
  "limits": {
    "users": 50
  },
  "installation_id": null
}
```

Формат может быть JSON + detached/embedded digital signature.

## 3. Генерация лицензии

```
Параметры клиента
        ↓
FK License Generator
        ↓
license payload
        ↓
подпись private key поставщика
        ↓
forestkeeper.license
```

## 4. Offline режим

Для закрытых контуров:
1. поставщик формирует подписанный license-файл;
2. администратор получает файл;
3. импортирует его через Admin Console;
4. License Service проверяет подпись;
5. лицензия активируется без Интернета.

## 5. Online режим

```
FK License Service → HTTPS → Forest Keeper Licensing Server
```

Online-режим не является обязательным для работы продукта.

## 6. Продление

Продление не требует переустановки продукта.

Offline:
- поставщик выпускает новый файл;
- администратор импортирует его;
- License Service заменяет действующую лицензию.

Online:
- License Service получает новую лицензионную информацию через защищённое API.

## 7. Истечение лицензии

Рекомендуемая модель:

```
ACTIVE → GRACE_PERIOD → READ_ONLY
```

Отдельное состояние `INVALID` используется, если цифровая подпись или содержимое лицензии не прошло проверку. `INVALID` не считается обычным истечением срока и должно обрабатываться как ошибка валидации лицензии.

После истечения лицензии клиентские данные не должны становиться заложниками лицензии.

В READ_ONLY должны оставаться доступны:
- вход администратора;
- просмотр данных;
- Audit;
- экспорт;
- установка новой лицензии.

Новые операции обработки могут быть заблокированы.

## 8. Использование и поддержка

Право пользоваться установленной версией продукта и право получать новые major/minor версии могут быть разными коммерческими правами.

Это решение должно быть оформлено отдельно в коммерческой модели.
