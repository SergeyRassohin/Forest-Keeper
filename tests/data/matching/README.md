# Учебные данные для проверки сопоставления

Это искусственные записи о материалах, созданные для тестов Forest Keeper. Данные заказчика и реальные выгрузки 1С не используются. Для примера из открытого источника есть отдельный [набор USGS](../external-review/README.md).

| Файл | Назначение | Тип источника в приложении |
| --- | --- | --- |
| [source-a.csv](source-a.csv) | 13 записей первого источника | FILE |
| [source-b.xml](source-b.xml) | 13 записей второго источника в синтетическом формате 1С | ONE_C |
| [records.json](records.json) | Исходные записи тех же тестовых случаев | Не загружать через UI |
| [gold.json](gold.json) | Заранее заданные тестовые метки пар | Не загружать через UI |

Порядок действий — [Quick Start, шаг 9](../../../docs/deployment/external-review-quickstart.md#9-сопоставление-и-ручная-проверка-идентичности). Оба пакета сначала нормализуются профилем `synthetic-material v1`, затем сравниваются matching-профилем с тем же названием. Это два разных профиля двух последовательных операций.

Ожидания до ручной проверки:

- В результате есть MATCHED, POSSIBLE_MATCH и NOT_MATCHED; соответствующие фильтры не пусты.
- MAT001: массы `12500 г` и `12.500 KG` становятся `12.5 kg`; карточка сохраняет оба исходных значения и provenance.
- MAT003: опечатка в имени требует проверки человеком, даже если score высокий. Автоматического fuzzy MATCHED нет.
- Одинаковое имя при разных сильных кодах не разрешает автоматическое совпадение. Пропуск пары ограниченным поиском не означает NOT_MATCHED.
- REVIEWER/DATA_OWNER может подтвердить либо отклонить POSSIBLE_MATCH с причиной. ADMIN без бизнес-роли и VIEWER этого сделать не могут.
- Ручной review определяет идентичность записей. Конфликт значений и Decision Registry появятся в следующих этапах.

`gold.json` использует независимые метки MATCH, NOT_MATCH и REVIEW. Поля `extra` вида A01/B01 обозначают тестовые случаи; все остальные межслучайные пары имеют NOT_MATCH. Эти метки не вычисляются matching-движком и не являются Forest Codex клиента. Тестовый benchmark измеряет качество на этом небольшом наборе; он не доказывает качество на промышленном домене.

Из каталога `backend`:

```bash
uv run --frozen python -m tests.benchmark_matching_quality
```

Пороги в offline sweep не включаются в runtime. Правила и ограничения описаны в [matching.md](../../../docs/development/matching.md).
